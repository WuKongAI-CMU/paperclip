## Canonical-doc target (5)

The canonical set is the docs that are **load-bearing for runtime decisions** *and* **read first by anyone joining mid-build**. Justification per pick:

1. **`INDEX.md`** — orientation north-star. Pinned by `README.md` as the "read first, 5 minutes" doc. Has the team table, the architecture diagram, the doctrine. Most-referenced from other docs.
2. **`PRODUCT-ARCHITECTURE.md`** — long-form architecture, sprint timing, doctrine §9.0, role registry §9.4, MVP boundaries §14. The doc that gets the P0 carve-out amendment.
3. **`OPENCLAW-INTEGRATION-ARCHITECTURE.md`** — downgraded but still canonical for the P1+ wire-up plan. Status banner gets added at top.
4. **`POLSIA-NAIVE-CODE-REUSE-MASTER-PLAN.md`** — ticket-level work breakdown. The doc that says what's left to ship and where the source material is.
5. **`BUILD-STATE.md`** — verified-build journal (15.4K lines). Live-rolling, but it's the only place where "this is what shipped today and what verifies it" is recorded. Anyone debugging "did X land?" reads this. Keep canonical despite size.

The current `README.md` (97 lines, last touched 2026-05-12) is **kept top-level as a folder navigator**, not counted as one of the 5 canonical docs — its only job is to point at the 5 above. After this audit it should be edited to reference exactly those 5 + this audit + the P0 cut + governance.

`REUSE-IMPLEMENTATION-LEDGER.md` (4399 lines, last touched 2026-05-12) is **kept top-level as an operational ledger**, not canonical doctrine. It's actively appended; archiving it would break in-flight work. But it's not what someone reads to learn the product.

`AUTOMATION-RELIABILITY-COST-POLICY.md` and `REBRAND-AND-PROVENANCE.md` are **governance** — kept top-level, referenced from `README.md`, but not read for product decisions.

## Delete justifications (every claim cited)

The 16 delete candidates are all already banner-marked as superseded by `README.md:71-73`. Specifically:

> "## Superseded (do not follow as guidance)

This audit's recommendation: archived-and-superseded is a half-measure that keeps the docs in `git grep`, in LLM context windows, and in onboarding-confusion. **Delete is the cleaner action** — git history preserves them. The two minor adjustments to the README's superseded list:

- `PAPERCLIP-EVALUATION.md` — README puts it in the superseded list, but the substrate decision is closed and the doc is the historical record for *why*. Treat as `research`, not `delete` (corrected above).
- `ARCHITECTURE.md` (no `-PART-N` suffix) — README lists `ARCHITECTURE-PART-2.md` and `ARCHITECTURE-PART-3.md` but not `ARCHITECTURE.md`. The base file is similarly stale; deleting all three together is consistent.

If preference is for safety-first archive over delete, the alternative is `git mv` each into `docs/dearme/research/superseded/` instead. Recommend `delete` because the superseded list has been growing for two months without anyone reaching back to those files.
